# Codex 历史记录浏览与导出

Windows 本地桌面工具（PySide6 6.9.3，当前版本 1.0.41）。默认读取 `%USERPROFILE%\.codex\`，也支持 `CODEX_HOME` 和界面中的目录选择。会话内容只在本机读取和导出，不调用 AI 服务。

## 启动

双击 `启动工具.bat`。如果 `dist\CodexHistoryViewer\CodexHistoryViewer.exe` 已存在，脚本直接启动 EXE；否则会创建项目内虚拟环境并安装依赖。首次从源码启动需要 Python 3.10+ 和网络下载 PySide6、zstandard。已有发行包可在无 Python 环境的 Windows 机器运行。

启动后选择一个或多个会话，可按标题、ID、正文和工作目录搜索，筛选 Codex / ChatGPT 网页来源、日期及归档状态，并在下方预览。来源说明栏会显示各来源数量及仅有目录元数据的数量；来源类别表示平台，不等于模型类别，Codex 中使用 GPT 模型的会话仍归为 Codex。后台筛选尚未完成时，列表操作和“导出当前结果”会暂时禁用，避免使用上一批筛选结果。列表会显示当前匹配数以及已选总数和其中属于当前筛选的数量；“将当前结果加入选择”会保留筛选范围外原有选择，“清除选择”则清除全部选择。“导出当前结果”只导出当前筛选可见的会话，“导出所选”只导出勾选的会话。点选一行后使用“预览当前行”，可以避免多选时预览到其他会话。来源类别、物理数据来源和读取状态集中显示在一列，悬停可查看完整信息。“本地文件大小”列统计该会话 rollout 和明确关联附件的逻辑文件大小，不代表 NTFS 实际分配空间；同一附件被多个会话引用时，当前结果合计会按会话重复计入。共享 SQLite 数据库与索引文件不能准确拆分到单条会话，会显示为“共享数据库 / 索引”；无法完成统计和找不到文件会分别计数。窗口位置和大小、列表列宽及预览区比例会保存到本机应用设置中，不保存聊天内容或 Codex 目录内容。日期范围按会话创建日期筛选；缺少可识别创建时间的会话不会匹配该范围。扫描与导出运行在后台线程，可取消；中途取消的会话目录会保留 `未完成.txt` 标记。

标题优先显示 Codex 已保存的具体标题。标题为空或是“未命名会话”“未命名绘画”“Untitled”等通用占位名时，使用会话中第一条有文本的用户消息作为标题（换行会压成空格，最多 100 字符）；只找到助手或工具内容时保留“未命名会话”。SQLite-only 会话会按检测到的序号/时间字段寻找第一条用户消息。若数据库没有可识别的顺序字段，SQLite 无法证明消息先后，标题回退只能按数据库返回顺序尽力选择。

## 跨电脑导入

工具会记住最近一次扫描的目录。导入成功后，关闭再打开仍会显示导入库；要查看这台电脑自己的会话，可在路径框恢复本机 Codex 目录并点击“扫描 / 刷新”。

导入选项会让你选择 ZIP 文件和本机导入库保存位置。导入完成后列表自动切换到导入库，所以另一台电脑可直接浏览这些会话；导入库与目标电脑自己的 Codex 目录分开保存，可通过路径框切回原目录。每条会话清单中的文件会校验 SHA-256；未完成、缺失或校验不符的包不会留下半成品。带有原始记录的包会逐份保留所有 rollout 文件。

在另一台电脑上点击数据目录右侧的“导入包…”，选择本工具导出的 ZIP，再选择本机导入库保存位置。工具会在后台安全解压、校验路径并建立本地只读浏览目录，完成后自动切换到导入数据并显示会话列表；原来的 `%USERPROFILE%\\.codex` 数据不会被修改。导入库可以移动或再次通过路径框打开。

导出包含原始 JSONL / ZST 时，导入优先使用原始记录；只包含 JSON 阅读版时，工具会根据 `聊天记录.json` 建立可浏览的重建记录，并在会话状态/读取报告中标明这是导入包重建内容，不能当作原始 JSONL。导入包必须包含每个会话的 `manifest.json` 和 `聊天记录.json` 或原始记录；不会导入 `auth.json`、凭据文件或 ZIP 外部路径。

如果双击 EXE 后窗口立即消失，请使用 ZIP 中的“启动工具.bat”，并保持 `dist\\CodexHistoryViewer\\_internal` 文件夹与 EXE 同时存在。启动失败时脚本会暂停并显示日志位置；EXE 直接启动失败时诊断日志写入 `%LOCALAPPDATA%\\CodexHistoryViewer\\启动错误.log`。

会话类别依据数据库明确保存的来源字段（如 source_kind）或可识别的 Codex rollout 文件判断，不根据模型名或聊天内容猜测。部分数据库只保存会话目录元数据，可能没有聊天正文或附件；工具会在状态、预览和导出报告中标明缺失，不能将元数据导出称为完整聊天记录。Codex 会话即使使用 GPT 模型，也仍归为 Codex。

## 导出格式

- TXT、Markdown、HTML 和 JSON 都支持“纯聊天版”和“完整版”。纯聊天版仅含用户和助手消息；完整版增加工具调用、工具结果、状态及未知事件。
- HTML 是内嵌样式的静态离线页面，记录内容经过 HTML 转义，没有外部脚本或资源。
- JSON 导出会将长字符串分块写入，并在分块期间响应取消；取消时临时文件会清理，不会留下可误认为完整记录的 JSON 文件。
- TXT、Markdown 和 HTML 按事件及文本块逐步格式化写入临时文件，不再拼接整篇文档；HTML 仍对每块消息内容转义。取消或写入失败会清理临时文件，完成后再原子发布。
- 阅读版只投影格式需要的字段，不再为 TXT、Markdown、HTML 复制事件中的完整原始 JSON 数据；JSON/ZIP 仍按所选内容保留结构化记录。
- 原始 JSONL / ZST 选项按字节复制原始 rollout 文件；它不应用脱敏。勾选时需要额外确认，归档输入仍以原 `.jsonl.zst` 保存。
- ZIP 包含会话记录、会话关联附件和 `manifest.json`。每条会话有独立目录；同名目录和文件会自动加序号，不覆盖已有导出。
- 可选脱敏会替换常见 `password`、`token`、`api_key`（包括 `OPENAI_API_KEY`）、`access_token`、`refresh_token`、`client_secret`、`private_key`、Bearer 凭据、PEM 私钥格式及常见绝对本地路径。它是启发式处理，不能保证发现所有敏感值。脱敏位置会以 `[已脱敏: …]` 标出；导出失败或取消时也会先脱敏报告和标记文件。
- 文本脱敏也识别 JSON/YAML 中带引号的敏感字段名，以及同一行内完整闭合的 `password="含空格的值"`；绝对路径在流式文本附件中也会脱敏。跨行或未闭合的敏感引号值无法可靠判断边界，脱敏导出会失败或跳过附件，不会复制原文。规则仍是启发式，不能替代人工检查。
- 会话记录脱敏按文本行分段，保留跨行 PEM 私钥处理，并在分段期间响应取消。单行超过 1 Mi 字符、跨行引号敏感值或未闭合引号敏感值时，脱敏导出会失败并保留错误标记，不会回退为明文。
- 导出位置必须在所选 Codex 数据目录之外。数据库中的会话路径也会限制在所选目录内；符号链接记录文件和数据库不会作为数据源跟随读取。
- 附件只从消息内容中的明确附件引用和 `imageView` 记录复制，不再把工具或未知事件中的任意 `file_path` 当附件。常见凭据和配置文件名（如 `auth.json`、`.env`、密钥文件）会跳过并记入清单。
- 认证配置附件如 `.npmrc`、`.pypirc`、`.netrc`、Git 凭据文件及 Docker 凭据配置也会跳过并记入清单，避免因无扩展名而绕过文本脱敏。
- 开启脱敏时，UTF-8 和带 BOM 的 UTF-16 文本附件会先脱敏到临时文件，再以原子方式发布；跨行敏感引号值、无法安全解码或取消中的附件会跳过或清理暂存文件并报告，不会退回原样复制。
- 文本附件脱敏按行流式处理，避免把整个大文件读入内存；单行超过 1 Mi 字符时会安全跳过并写入报告。附件复制按 1 MiB 分块，可在复制大型附件时响应取消，并清理未完成的目标文件。
- 预览最多显示约 100 万字符，超出时明确标注截断；预览可通过底部“取消”按钮中止。完整内容仍可通过导出保存。
- 搜索输入做了短延迟合并，减少大列表每次按键时的重复渲染。取消会覆盖扫描、哈希、ZIP 和 TXT/Markdown/HTML 格式化阶段，并在事件之间响应；关闭窗口时会等待后台线程退出后再清理临时快照。
- 预览、扫描和导出互斥运行；预览完成、失败或取消会更新状态。批量导出报告会列出尚未开始会话的 ID、标题和状态；即使首个会话前取消或没有选择会话，也会创建输出目录并写出报告。单个会话初始化失败会写入报告并继续处理后续会话。
- JSONL 或数据库中的条目 `type` 字段若不是文本，会按未知记录保留并写入报告；单条异常不会中止后续有效记录。无法转换的超大时间戳保留原值，不会中断文件扫描。
- 脱敏导出模式下，批量报告也会脱敏失败标题和错误文本，避免失败信息绕过会话正文脱敏。
- 脱敏导出时，附件文件使用内容无关的散列名，避免原文件名中的口令或令牌泄漏；JSON 中的读取报告和附件文件列表也一并脱敏。
- 内嵌 base64 图片按小块解码，可响应取消并清理不完整文件；JSON 附件引用使用导出目录内的相对路径，不把原始绝对路径或整段 data URL 重复写入。
- ZIP 先写入 `.partial` 临时包，写完并计算哈希后再改名为正式 `.zip`；中断不会留下看似完整的 ZIP。附件引用路径包含符号链接时会跳过，避免通过目录链接读取凭据。
- ZIP 使用同目录的独占随机临时文件，并以不覆盖方式发布；已有同名 `.partial` 文件或链接不会被截断。附件、原始记录及其目录中的 Windows junction 也会跳过。
- 取消导出时也会尽力写出 `complete=false` 的 manifest，列出已生成文件；未完成哈希的文件会明确标为未计算，不能误认为是完整包。ZIP 发布前会逐成员解压校验 CRC，校验过程仍可取消。
- 原始 rollout 复制时会比较打开文件的前后大小、修改时间与文件身份；发现会话正在写入或文件被替换时会在清单报告中注明，保留原始副本供用户判断。
- 会话表改为 `QTableView` 按需读取单元格，避免每个会话都创建 12 个表格单元格对象；数据库回退搜索文本以有界列表累积，避免长记录反复复制字符串。
- 会话搜索在后台线程执行；新筛选会取消过期任务并只显示最新结果。正文搜索索引在扫描阶段一次性做 Unicode 大小写折叠，避免每次按键都拼接和复制整段聊天正文。
- `session_index.jsonl` 只保留会话 ID、标题和更新时间字段；损坏的索引/历史行按错误类型聚合并最多保留 5 个行号样例，避免异常文件让读取报告随坏行数量无限增长。`history.jsonl` 字段名摘要最多显示 128 项。
- 附件复制期间取消会立即中止当前会话导出，不会把取消误报成目录读取错误，也不会继续生成所选阅读格式。
- 预览最多读取 20,000 条源记录（rollout 与 SQLite 回退共用额度）和约 984,000 个消息文本字符；达到文本上限后不会再累计后续事件文本，界面再为标题和报告保留空间。预览还会在整条会话中共享最多 5,000 个关联附件文件检查额度和 50,000 个附件目录项额度；达到上限的附件状态会标为“预览上限，未检查”，不会当作缺失。完整导出仍读取全部可用记录。这样预览超长会话时不会为了显示有限文本而先把整段会话事件或附件清单都载入内存。
- 预览始终使用当前行；没有当前行时，仅在只勾选一个会话的情况下使用该会话，多选时会提示先点选一行。切换 Codex 数据目录后清除旧目录的勾选；超大批次的界面结果预览最多显示 50 条，完整结果仍保存在 `导出报告.json`。
- 附件和会话目录遇到系统拒绝访问等遍历错误时，会把失败位置写入读取报告；导出目录在生成清单或 ZIP 时无法完整枚举则会标记导出失败，避免产生缺项但看似成功的包。
- 附件目录遍历会在每层目录检查取消，包括空目录树；取消后不会继续扫完大量空目录。
- 会话文件发现和预览附件枚举使用可取消的逐项目录扫描，避免先把单个超大目录的全部名称载入内存；文件属性竞态会进入读取报告，不会中止其他会话扫描。
- 同一导出目录中的并发批量导出会用原子、不覆盖的方式发布导出报告，分别保留各自结果。
- 导出清单会为子目录中名为 `manifest.json` 的附件照常计算 SHA-256；仅会话目录顶层 manifest 不在自身清单内。
- 扫描记录时缓存当前最新时间的比较值，避免对每条记录重复解析同一个时间戳；读取响应条目后会跳过已有相同 ID 的 `item_completed` 副本暂存，降低大消息的重复内存占用。
- 无条目 ID 时，重复检测按排序后的消息正文计算规范哈希，不受 JSON 键顺序、空白和 rollout 外层时间/序号影响；相同内容的响应记录、完成事件与数据库投影能一致去重。
- HTML 中附件相对路径会进行 URL 编码并转义，文件名含空格、`#`、`?`、`%` 或中文时，离线链接仍能正确打开。

每个会话目录中的 `manifest.json` 包含工具版本、UTC 导出时间、会话来源路径、记录计数、重复条目计数、文件字节数与 SHA-256、缺失附件和读取错误。清单不计算自身哈希以避免自引用。批量导出另生成 `导出报告.json`，并记录 ZIP 文件自身的 SHA-256。

## 已实现的数据兼容

以下路径和格式用于兼容探测；不同电脑、Codex 版本和安装可能存在差异，工具会动态检测可用来源，不假设所有项目都存在：

- `sessions/YYYY/MM/DD/rollout-*.jsonl`：顶层记录由 `type`、`timestamp`、`ordinal`、`payload` 组成；正文在 `response_item`，工具结果和状态主要在 `event_msg`。
- `archived_sessions/rollout-*.jsonl.zst`：压缩的 JSONL，需 `zstandard`。
- `archived_sessions` 下的嵌套目录也会按归档会话处理。
- `session_index.jsonl`：记录 ID、线程名和更新时间等索引信息；只补充标题/时间，不用作聊天正文。
- `history.jsonl`：只作为可能的辅助历史，不作为完整对话读取。
- `state_*.sqlite`：动态检查表和列后读取会话元数据。
- 其他 SQLite 数据库：仅在动态发现与会话有关的表和字段后尝试读取；结构不同或没有正文时会在状态和报告中标明。
- SQLite 中即使只有已识别的会话条目表、没有元数据表或 rollout 文件，也会按 `thread_id` / `session_id` 创建会话；每张表最多发现 100,000 个不同会话 ID，超限和异常 ID 会写入报告。能使用会话 ID 索引且不需要临时去重表时保留索引 DISTINCT 查询；其他表最多扫描 1,000,000 行，达到上限会报告可能遗漏后续会话。
- 数据库 JSON 字段支持 UTF-8 文本和 UTF-8 BLOB；回退预览只读取条目字段、时间和排序所需列，不载入同一行里无关的大型 BLOB。
- SQLite 查询可响应取消；数据库回退只代表当前快照中可识别的投影数据，不保证包含完整会话。
- SQLite-only 搜索对每个数据库复用一个只读连接；有 ID 索引时按会话读取，无索引时用连接内临时 ID 表单次 JOIN 扫描目标记录，减少大量会话下的重复全表读取。取消会中止查询，并保留部分读取状态。
- 批量导出多个 SQLite-only 会话时，会在 Codex 数据目录之外创建的临时一致性快照上，为相关的无索引条目表建立一次性查询索引，避免每个会话都重扫整张表。索引只写入应用临时快照，不修改原数据库；无法建立索引时会在导出清单中报告，导出仍会继续。
- 导出时，如果 rollout 行损坏、读取失败，或 SQLite 会话更新时间明显晚于 rollout 最后记录时间，会按已检测到的表结构尝试补读 SQLite 条目；已有条目 ID 或相同内容会去重。单 rollout 且两边都有可用序号时按序号合并；无法证明跨来源顺序时会把数据库条目放在 rollout 后并在清单中说明。
- 健康 rollout 默认不会逐会话扫描无索引的 SQLite 条目表，以免整批导出退化为每个会话重复全表扫描。检测到损坏或时间差时仍会尝试该表，并在读取报告标注扫描影响。
- SQLite 元数据与条目查询只投影需要的列，避免把同一行里的大型无关 BLOB 载入内存；会话 ID 按游标逐项处理，并限制每张表最多 100,000 个不同 ID。
- 数据目录无效或无法枚举时会显示读取错误；取消读取时会停止延迟事件的后续规范化，并在报告中标明事件列表不完整。
- `thread_history_*.sqlite`：动态检查 JSON 条目表。推理类条目会跳过。
- SQLite 条目字段除显式 JSON 列名外，也会对含会话 ID 的候选表做只读内容抽样，以识别名称不同的 JSON 字段；抽样最多检查 5 条且跳过大于 4 MiB 的单条值。
- SQLite 以 `mode=ro` 打开后通过 SQLite Backup API 创建临时一致性快照，从而纳入已提交的 WAL 内容；快照放在系统临时目录，退出时清理，不修改源数据库。
- 附件只从 `attachments\<会话 ID>` 目录、记录中明确引用的 `attachments\<UUID>` 子目录及明确引用的文件读取；不会扫描或打包无关附件目录。

## 覆盖范围与限制

rollout JSONL 是消息、工具调用和状态的主要来源。`thread_history` 是投影数据，可能落后于正在写入的 rollout，也可能只保留部分会话条目；补读数据库可修复已识别的缺口，但不能据此宣称完整恢复。时间戳缺失或不可靠时，恰好截断在完整 JSON 行边界的 rollout 可能无法自动识别；健康 rollout 对无索引数据库表也不会逐会话全表扫描，此时清单会提示无法核对额外记录。单表超过 100,000 个不同会话 ID 时，后续 ID 不会列出，报告会注明上限。没有可用 ID 索引的条目表最多检查前 1,000,000 行；若达到该上限，后续会话可能未列出，读取报告会明确标记。数据库中没有正文、源文件缺失或损坏时，工具会保留会话元数据并在状态、预览及清单标记“未找到”或错误。

阅读版会按条目 ID 或完全重复的记录去重；原始导出不改写原文件。已识别的 `reasoning`、加密思考内容和 `analysis` 阶段不导出。未知记录类型会保留为未知事件并计入读取报告。扫描 JSONL、辅助索引和数据库条目按行或按游标读取；已有条目 ID 时直接按 ID 去重，仅对缺少 ID 的条目计算备用哈希。UUID 附件目录在单次会话读取中缓存，避免重复消息反复遍历同一目录。预览及不含 JSON 的导出不会把原始事件对象保留在规范化结果中；JSON/ZIP 为保留完整字段仍会载入原始字段。JSON 文件逐事件写入临时文件，避免再复制完整的事件树，纯 JSON/ZIP 导出也不会构造不需要的 TXT/HTML 事件副本。界面正文搜索索引每个会话最多缓存 256,000 字符，超出部分仍可在导出和预览时读取，但不参加列表正文搜索。规范化事件目前仍会按会话暂存在内存中，所以特别大的单条会话可能占用较多内存；预览最多显示约 100 万字符。

会话附件目录按会话 ID 关联。记录中明确提到 `attachments\\<UUID>\\...` 的 UUID 子目录也会作为该会话附件读取；只检查被引用的子目录，不遍历打包其他附件。单条消息和附件之间没有可靠关联时，附件会被复制到会话目录，但消息不会被强行绑定到某个文件；缺失引用会报告。外部路径附件只在会话记录明确引用时尝试读取。

## 从源码启动和打包

也可以在命令行运行：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

运行 `构建EXE.bat` 会安装打包依赖并生成 `dist\CodexHistoryViewer\CodexHistoryViewer.exe` 及其 Qt 运行文件。请保持 EXE 所在目录完整；启动脚本会直接运行这个 onedir 发行包。EXE 不是代码签名发行版，首次运行时 Windows 可能显示常规下载文件提示。

构建完成后可运行 `打包发行包.py`，在上级 `outputs` 目录生成 Windows 使用包和完整源码包。脚本会校验 ZIP CRC、启动文件、EXE 和中文文件名编码，并打印归档 SHA-256。
